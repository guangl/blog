发布变更前逐条过一遍，比事后回滚便宜得多。

## 变更前

- [ ] 确认目标实例与角色，别在生产主库上试。
- [ ] 记录当前参数值，作为回退依据。
- [ ] 涉及 DDL 的，确认是否需要 `CONCURRENTLY`。
- [ ] 评估锁等待时间与业务影响窗口。

## 执行中

- [ ] 观察 `pg_stat_activity` 中的活跃会话与锁等待。
- [ ] 关注复制延迟，避免回放跟不上。

```sql
SELECT pid, state, wait_event_type, wait_event, left(query, 60)
FROM pg_stat_activity
WHERE state <> 'idle'
ORDER BY query_start;
```

## 变更后

- [ ] 用与问题现象对应的检查验证结果。
- [ ] 保留观察窗口，不立刻下线。
- [ ] 更新变更记录与相关文档。

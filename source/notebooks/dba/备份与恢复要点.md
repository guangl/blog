备份的价值只有在恢复成功的那一刻才成立。

## 逻辑备份

```bash
pg_dump -Fc -d database_name -f backup.dump
```

自定义格式（`-Fc`）支持并行恢复和选择表恢复，比纯 SQL 文本更实用。

恢复前先验证备份可读：

```bash
pg_restore --list backup.dump | head
```

## 物理备份

- 使用 `pg_basebackup`，并确认 WAL 归档持续可用。
- 恢复演练要包含「恢复到任意时间点」的场景。
- 定期检查归档目录是否堆积，避免磁盘被写满。

## 需要确认的问题

- [ ] 备份保留周期是多久？
- [ ] 最近一次恢复演练是什么时候？
- [ ] 备份文件是否与数据库在不同故障域？
- [ ] 恢复演练有没有覆盖到时间点恢复（PITR）？

## 恢复验证

演练恢复后至少确认：

```sql
SELECT count(*) FROM 关键业务表;
-- 与预期行数比对，确认数据完整
```

只验证「服务能起来」不够，要验证数据本身对得上。
